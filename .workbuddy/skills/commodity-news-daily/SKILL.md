# 每日新闻采编与日报生成

本技能是该项目唯一采编入口。**用户只发一句采编指令，你必须自动完成全部六个环节，中途不要求用户补发任何指令。**

## 前置（每次执行前）

1. 先完整阅读项目根目录下的 `WORKBUDDY_INSTRUCTIONS.md`，以其为最高执行规范。
2. **网络体检（必做，约 10 秒）**：运行 `python3 preflight_net_check.py`。
   - 退出码 0 → 继续；
   - 退出码 1（致命故障）→ **停止采集**，把失败清单与处置建议原样告诉用户（多为代理节点失效或未开 TUN 模式），修好后再重跑本步；
   - CME/Nasdaq/LME 显示 WARN 属正常（站点反爬），不阻断。
3. 运行环境自检：优先使用本机已装好依赖的 Python 解释器（run.sh 会自动探测候选路径；也可手动 `python3 -c "import playwright, bs4, feedparser, pypdf, googlenewsdecoder"` 验证）。

## 执行链条（指令 → 六个环节）

用户指令映射：

| 用户说 | 执行 |
|---|---|
| 爬取今天的一类新闻并生成日报 | `python3 run_daily_pipeline.py --category 一` |
| 爬取今天的二类新闻并生成日报 | `python3 run_daily_pipeline.py --category 二` |
| 爬取今天的三类新闻并生成日报 | `python3 run_daily_pipeline.py --category 三` |
| 爬取 YYYY-MM-DD 的一类新闻 | `python3 run_daily_pipeline.py --category 一 --date YYYY-MM-DD` |

每个指令的完整链条：

1. **Wave 1–3 采集**：运行上述流水线命令（策略 A 官方源 / 策略 B FOW 与 Mondo Visione / 策略 C 彭博穿透）。
2. **Wave 4 合并**：manifest 合并、跨源去重、全局重编号。
3. **Wave 5 出报**：编译三段式日报（一、交易所动态 / 二、市场动态 / 三、监管动态）。
4. **Wave 6 终审四查（强制，见 `WORKBUDDY_INSTRUCTIONS.md` 第六节）**：
   - 查主题相关性：剔除与大宗商品、衍生品、交易所、金融监管无关的泛科技/泛金融公关稿（纯 AI 发布、电商/支付功能、加密行情评论、培训招生、会议预告、数字身份/HR 科技等）；
   - 查时效：剔除旧稿与已失效公告；
   - 查重复：同一事件多源只留一篇；
   - 查幻视：正文专名与数字必须能在存证 PDF 原文中找到，找不到即剔除或依据原文重写。
5. **收尾**：删除被剔除条目的 PDF 与 manifest 记录，全局重编号使 [1]~[N] 连续且与 PDF 文件名前缀一致。
6. **门禁复核**：运行 `python3 report_quality_checker.py --dir "<目标存证目录>"`，四大红线全绿方可交付。

## 交付

- 日报落盘：`{config.json 的 obsidian_news_dir}/{YYYY-MM-DD} 新闻（类别后缀）/`（路径未配置时自动回退本地工作区并提示）。
- 向用户汇报：终稿篇数与板块分布、终审剔除篇数及理由、门禁结果、存证目录位置。
- 若官方源采集为零（日报只剩 Mondo Visione 等个别来源），主动提示用户检查国际网络/代理（见手册 FAQ Q0），不要静默交付残缺覆盖的日报。

## 铁律

- 门禁未全绿不得交付；宁可少几篇，不可混一篇主题无关稿。
- 严禁凭印象编造正文；一切数字与专名回溯存证 PDF。
- 命名铁律：目录与日报文件名带中文全角括号类别后缀（一）（二）（三）。
